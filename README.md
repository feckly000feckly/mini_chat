# Проект приложение с клиентской частью и HTTP-бэкендом. написан с частями **C++23** но не весь.

## Структура проекта

/front — фронтенд, сгенерированный полностью от начала до конца.
/core — серверная часть (backend). Весь код написан вручную, без генерации.

на самом деле пишу впервые на слоистой архитектуре да и проект такого типа

в проекте есть заранее скомпилированный исполняемый файл
  Класс:                             ELF64
  Тип:                               DYN (Position-Independent Executable file)
  Машина:                            Advanced Micro Devices X86-64


## Зависимости

* **C++23**
* **Crow** (header only)
* **SQLite3**
* **nlohmann/json** (header only)

## Компиляция

не хотел использовать CMake, Makefile

### Debug

для сборки Debug-версии:

g++ test.cpp -lsqlite3 -std=c++23 -g -fsanitize=address -fsanitize=undefined

(дебаг символы и санитайзеры)

### Обычная сборка

g++ test.cpp -lsqlite3 -std=c++23

## Проброс порта при тестировании в NAT-сети

если сервервак запущен на 127.0.0.1:9090, а доступ к нему требуется из внешней сети, можно сделать:

sudo iptables -t nat -A PREROUTING 
-s 192.168.1.10 
-p tcp 
--dport 9090 
-j DNAT 
--to-destination 127.0.0.1:9090

192.168.1.10 необходимо заменить на свой локальный IP-адрес.

(если в какой то цепи заблокирована политика то придется добавлять отдельное правило )

в веб клиенте тоже нужно сменить url с лупбэка на локальный

# HTTP API

API использует HTTP-запросы и JSON, но **не REST API**.

## Отправка сообщения

**POST /send**

curl -X POST http://127.0.0.1:9090/send 
-d '{ "id_user": 1, "id_message": 101, "data_message": "Привет! Это тестовое сообщение" }'

## Удаление сообщения

**POST /delete**

curl -X POST http://127.0.0.1:9090/delete 
-d '{ "id_message": 101 }'

## Получение истории сообщений

**GET /history**

curl http://127.0.0.1:9090/history
